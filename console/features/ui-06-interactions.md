## 8. 交互细节与状态

### 8.1 状态色与状态集（双主题各一套底色；**6 态**）

**状态集（唯一权威，原型 `PH`）**：

| 状态 | 图标 | 中文 | Light 底 / 字 | Dark 底 / 字 |
| --- | --- | --- | --- | --- |
| `Succeeded` | ✓ | 成功 | `#E6F4EA` / `#1E8E3E` | `#12351F` / `#5DDC86` |
| `Running` | ● | 运行中 | `#E8F0FE` / `#0066CC` | `#12304D` / `#6FB4FF` |
| `Failed` | ✕ | 失败 | `#FCE8E6` / `#D93025` | `#3A1A17` / `#FF7B6E` |
| `WaitingApproval` | ⏳ | 待审批 | 告警底 / 告警字 | 同左（双主题各一套） |
| `Pending` | ○ | 待执行 | `#F1F3F4` / `#5F6368` | `#24282F` / `#98A0AD` |
| `Paused`（Rollout 任务级） | ⏸ | 已暂停 | 告警底 / 告警字 | 同左 |

> 状态徽章 = **图标 + 文字 + 色块**三通道，**灰阶下仍可辨**（呼应 S4）。
> 原型实现：`PH` 映射（`succeeded/running/failed/waiting/pending/paused`）+ `badge(p)`；`waiting` 与 `paused` 共用告警底色但图标不同（`⏳` vs `⏸`），**不靠颜色区分**。
> ⚠️ **实现差异（2026-10-08 核对）**：console 实现的状态集 = `PipelineRunPhase` 六枚举 `Pending / Running / WaitingApproval / Succeeded / Failed / Cancelled`（`src/api/run.ts`），**无 `Paused`**（Paused 是 Rollout 任务级状态，不在运行枚举内）；且 `StatusBadge.vue` 仅 5 档样式（succ / run / fail / warn / pend）—— **`Cancelled` 无专属色，落入 default `pend` 灰**（与 Pending 同档渲染）。

- DAG 节点描边：成功 1px 绿 / 运行 2px 蓝 / 待执行 1px 灰 / 失败 1px 红（粗细区分"已完成/当前活跃"）。
- 步骤器节点同规则，active 步骤 2px 蓝；箭头与左节点状态同色。
- KPI 数值 Ink / Action Blue，指标向好时用绿（Succeeded 语义）、变差用红（`bad-num`）。

### 8.2 各页面四态（空 / 加载 / 错误 / 成功）—— 双向钢人论证后补充

> 先不盲目给每页塞四种状态。对每类状态做"是否必要 + 触发条件 + 替代方案"的双向论证，再落到逐页映射。结论：**加载态收敛为"路由首屏骨架"，轮询刷新不进加载态；成功态不作独立整页态（用 toast + 数据呈现）；空态与错误态是真正必须设计的两种。**

**状态分类论证**

| 状态 | 正方（必须有专门态） | 反方（可省 / 降级） | 结论 |
| --- | --- | --- | --- |
| 加载态 | 首屏无数据时应占位，防"白屏被误判为坏了" | 应用每 2~3s 轮询，若每次轮询都弹骨架会闪烁；数据已呈现时轮询只是后台更新 | **仅路由首次加载用骨架屏**；轮询刷新只加极轻量"刷新中"点状指示（或不显式提示），不进入加载态 |
| 空态 | 首次使用（用户自建集合：流水线/运行/发布/配置/制品）无数据时，需引导"如何创建" | 项目用读时播种默认数据（seed-on-read；服务树/组件有默认值），核心实体不易空；空态仅作用于用户生成集合 | **必须有，但作用域收敛到用户生成集合**；首屏给出"新建"引导而非空白 |
| 错误态 | 网络/5xx/404/权限必须可见，否则用户以为卡死 | 过度错误态会吓人；部分错误可被轮询自愈（临时断网恢复后数据回来） | **必须有，且区分"可重试"与"终态"**：网络/5xx→重试按钮；权限拒绝→引导申请 role-binding（见 §1.2、§7.9），不只是一句报错 |
| 成功态 | — | 控制台里"成功"通常是瞬时确认 + 数据出现，独立整页成功态罕见且易过度设计；运行监控的 Succeeded 是**数据态**（§8.1 状态色）而非页面态 | **不作独立整页态**：用 toast + 数据呈现（如列表新增一行、运行变绿）；仅运行监控通过 §8.1 状态色表达成功 |

**逐页四态映射**

| 页面 | 空态（作用域） | 加载态（仅首屏骨架） | 错误态 | 成功态（toast + 数据） |
| --- | --- | --- | --- | --- |
| 总览 Dashboard | 无空态（KPI 为 0 也算数据） | 首屏骨架 + KPI 卡占位 | 聚合接口失败→重试；异常 Runner 提示条（§7.2） | 刷新后数值更新（无独立成功态） |
| 服务树 | 极少空（读时播种默认）；真空闲时"暂无节点 + 新增子节点" | 树面板骨架 | 拉取失败→重试；无读权限→提示申请 | 新增节点后树展开并定位 |
| 组件详情（各 Tab） | 各 Tab 内用户集合为空时引导（如交付·流水线 无流水线→"还没有流水线 → ＋ 新建"） | Tab 首屏骨架 | Tab 数据失败→重试；无组件读权→引导 | 操作后对应行/项出现 |
| 流水线编排 | 无阶段→"新建第一个阶段" | 打开编排器骨架 | 保存/校验失败→行内定位到具体阶段/任务 | 保存 toast + 结构落盘呈现 |
| 运行中心 | 列表空→"触发一次运行"；筛选无命中→"无匹配记录"（原型 `noHit`） | 首屏表格骨架 | 进度接口失败→重试；被权限拦截→引导 | 状态徽章变化（§8.1 状态色），无独立成功页 |
| 发布 / 灰度 | 无发布记录→"发起一次发布"（原型 `无发布记录`） | 步骤器骨架 | 健康度拉取失败→重试；生产环境无审批权→引导 | 步骤晋升 toast + 权重变化 |
| 日志面板 | 日志为空（运行刚起/无输出）→"等待输出" | 流式连接建立中骨架 | 日志拉取/流失败→重试；无读权→引导 | 日志持续追加（流本身即"成功"） |
| 制品库 / 权限（列表页） | 集合空→"新建"引导 | 表格骨架 | 列表失败→重试；权限不足→引导 | 新增行呈现 |
| 环境（树 + 对接面板） | 无环境→"新建环境"向导；无主机→"添加主机"引导；未配置→"未配置"徽章（§7.12.6） | 树骨架 / 测试按钮 loading | 连接测试逐项 `✕` + 原因（§7.12.5）；凭据缺 `config:update`→引导 | 连接测试 "N/N 通过" + 状态点转绿；保存 toast |
| 删除确认弹窗 | — | 提交中禁用按钮 | `409` → 渲染后端 `reasons`（不删除） | 关闭弹窗 + 列表移除 + toast |

> 统一组件：`<EmptyState icon+title+action>`、`<ErrorState message+retry>`、`<Skeleton>`（仅首屏）、`<Toast>`（成功/轻错）。空/错态需接"申请权限"入口（见 §1.2、§7.9）。

### 8.3 关键交互反馈规则

- **新建/删除流水线**：删除**必须强确认（输入名称）**（见 §7.4）；新建保存后直接进编辑器（减少一次点击）。
- **编排页返回**：若有未保存配置，先弹确认「配置未保存，是否返回？」（原型 `backFromEditor`）。
- **主题切换**：即时生效、记住选择（`localStorage`）；首次访问跟随系统 `prefers-color-scheme`。
- 触发运行：对话框校验目标必选（无可用目标时「▶ 触发」禁用）；提交后 toast + 跳**该次运行的监控页** `/pipelines/:id/runs/:runId`（`TriggerRunDialog` emit `triggered`，`PipelinesTab` 与 `PipelineEditorView` 两处入口均如此跳转）。对话框另含**制品版本 picker**（B-20 最小版：一键填入 `VERSION` 参数）、组件参数 key 预置、策略拒绝 `409 + reasons` 原样渲染（2026-10-08 按实现回写）。
- 重新投递：`run.phase === 'Failed'` 或 run 有 `message` 时显示按钮（`redispatch`）；**实现无确认步**，点击即调用，成功后 toast + 刷新——与原设计「需确认避免重复派发」不同，差异记录于此（`RunMonitorView.vue`）。
- 取消运行：**非终态**（`Pending`/`Running`/`WaitingApproval`）才显示按钮；**两段式内联确认**（刻意不用 `window.confirm`——内嵌预览下不可靠），终态由后端 `409` 兜底。相位判定在 `utils/run.ts` `isRunCancellable`，由 `scripts/run-control-smoke.mjs` 冒烟钉住。
- 单任务重跑：任务 `Failed`/`Skipped` 时（`utils/run.ts` `isTaskRerunnable`）在任务详情显示「重跑任务（含下游）」（`POST /runs/:id/tasks/:name/rerun`）；**实现无确认步**，点击即调用、toast 反馈——差异记录于此（`RunMonitorView.vue`）。
- 审批：批准 / 拒绝共用一个弹窗，**审批意见可选**（`RunMonitorView.vue`：`reason: approvalReason || undefined`，输入框 placeholder「可选」）——与原设计「均需填意见」不同，差异记录于此；拒绝后运行终止并标记（见 §7.9）。
- 参数管理删除：删除正常走 `DELETE`；前端失败分支的容错 toast 文案仍残留示意字样「（后端暂不支持）」（`ConfigTab.vue`，仅删除失败时展示）。
- 阶段/任务重排：阶段可前后移动（重排 `sequence`）、子任务可上下移动（重排 `displayOrder`），拖动/点击后即更新预览，不即时落库。

### 8.4 去冗余原则（v3 新增，用户反馈「页面有很多冗余」）

**原则一：评审信息不进产品 UI。** 后端依赖、契约待确认、字段策略等属**文档**内容，不应渲染成界面文案（真实产品不会对用户说"此端点后端暂缺"）。

| 冗余项 | 反例 | 处置 |
| --- | --- | --- |
| 后端依赖说明散落页面 | 6 处内联 `hint`：Dashboard(N-1) / 运行中心(N-2) / 服务树搜索(N-8) / 编辑器(N-4·N-5) / 搜索浮层(N-8) | 不渲染；收进顶栏 **「ⓘ 设计备注」开关**（默认关闭），按**视图**（原型 `noteKey()`）聚合展示，与文档附 A 同源 |
| 服务树页「为什么树不放左栏」规模自检表 | 整块表格渲染在页面里 | 不渲染；并入设计备注（原型 `NOTE.catalog`） |
| 「（示意）」等元前缀 | 混在正文里 | 仅保留在 toast（演示反馈）与「四态演示」控件上；正文标题不带"示意" |

**原则二：同一信息只出现一处（SSOT）。**

| 冗余项 | 反例 | 处置 |
| --- | --- | --- |
| 面包屑 | 顶栏一条 + 内容区再一条（组件/编辑器页），与页面标题共 3 处 | **只留顶栏一条**，中间层为可点链接；内容区不重复 |
| 组件详情「快速入口」按钮组 | 「编排/运行流水线」「配置参数与环境」= 主 Tab 的重复入口 | 不渲染；概览只保留 KPI |
| 服务树页「同级 Component」表 | 与左卡树重复展示同一批节点 | 不渲染；右卡为「节点信息」（路径/仓库/语言/流水线数） |
| Dashboard「最近运行（全局）」 | 与运行中心**同一张表、同一组列**（完整 5 行） | 设计为截 **3 行 + 「查看全部 42 条 →」**；**实现差异（2026-10-08 核对）**：实现为跨流水线聚合的**最近 5 条**（各流水线取前 5 条后按时间排序截断），列「运行 / 流水线 / 触发人 / 状态 / 耗时 / 开始时间」，行点击进运行监控页，**无「查看全部」出口**（`DashboardView.vue`） |
| 目标状态 | warnbox 叙述一遍 + KPI「在线目标 3/4」再说一遍 | KPI 保留数字并**可点直达接入管理页**，warnbox 只讲行动（离线→自动重放） |
| 流水线列表渲染 | 组件内列表**两套重复模板** | 抽 `pipelineRow()` / `pipelineHead()` 共用（v4.4 后只剩组件内一处消费方，函数保留以备复用） |
| 组件内流水线数据 | `PIPELINES.slice(0,3)` **不分组件**（进 comp-worker 也显示 comp-web 的流水线） | 按组件过滤：`filter(p => p.comp === S.comp)`，无数据走空态 |
| 状态图标 | `badge()` 用 ✓●✕⏸，待办卡另用 emoji ⏸✕〰；且「待审批」与「已暂停」共用 ⏸ | 统一一套字形：`✓ 成功 / ● 运行中 / ✕ 失败 / ⏳ 待审批 / ⏸ 已暂停 / ○ 待执行` |
| 编辑器 kind 标签 | 恒为 `build`（进 release 流水线也显示 build） | 跟随所选流水线的真实 `kind` |
| 环境树渲染 | 组件详情「配置」与「环境」两页各写一套 | 抽 `envTreeRows(m, opts)` 共用（原型已落地） |

**原则三：刻意保留的"重复"（不是冗余，勿删）。**

| 项 | 为什么保留 |
| --- | --- |
| 组件「交付→流水线」列表 vs 运行中心「运行」列表 | **作用域不同**：前者是"这个组件有哪些交付手段"，后者是"所有组件的运行态势"；列集与入口语义均不同 |
| 运行中心 vs Dashboard 最近运行 | 保留但**分层**：Dashboard = 速览（实现为最近 5 条、无「查看全部」出口，见原则二该行差异注记）；运行中心 = 唯一完整列表 + 筛选 |
| 服务树页内搜索 vs 顶栏 ⌘K | **分工**：页内 = 就地定位节点（含未展开的深层节点，服务端搜）；⌘K = 跨页跳转（组件/流水线/Service）。若嫌重叠，可将页内搜索降级为"仅过滤已加载节点"（待定，见附 A · N-11） |
| 「配置」页的左环境树 vs 「环境」页的分组树 | **同组件不同用途**：前者是"编辑哪个环境的 values"的选择器（只读定位），后者是"环境与分组的生命周期管理"（可增删改）。**只要两处都不重复渲染同一份"环境详情"，就不算冗余** |

> **v4.4 影响**：原「全局流水线页 vs 组件内流水线列表」这一行属于"作用域不同"的刻意重复，随全局视图取消而自然消解。

**原则四（v4 新增）：导航只放"恒定的功能分区"，不放"数据视图"或"随使用变长的列表"。**

| 反例 | 问题 | 处置 |
| --- | --- | --- |
| 「流水线」「发布」作为顶层菜单 | 二者是**同一批交付数据的不同切面**，不是功能分区；同类项继续膨胀（将来还有"制品/环境/审批"） | 并入「运行中心」做视图；导航只留一个巡视入口 |
| 「最近访问」作为固定分区 | 条目数随用户行为变化，**违反"左栏恒定"**；且它是"功能的功能"，不是功能本身 | 不设该分区；直达由 ⌘K 承担 |
| **单条目下的分组标题**（v4.1） | 一个分组标签下面只挂 1 个条目，标签不提供任何归类信息，只是占位噪声 | 合并为一段**不挂标签**的主区；分组标签仅用于确有多个同类条目的分区（「平台管理」2 项） |

> 判据：**一个导航项如果可以被表达为某个已有页面的一个筛选/视图，它就不该是导航项。** 反之，如果它是"用户来这里的理由"（总览、巡视、看资源、管平台），才配占一行。另：**分组标签是给"一组"用的**，只有一个成员时不加标签。

## 8.x P2 体验层设计（2026-10-08 收口，STATUS #23）

> 来源：原 `console/plans/CONSOLE-P2-UX-DESIGN-2026-10-08.md`（2026-10-08），闭环后折叠入本文件；运行详情页 URL 形态裁定另见 [ui-10 附 B.x](ui-10-decision-records.md)。状态以 STATUS §2 #23 为准。

### 8.x.1 日志下载 + 按 task 折叠 + 流式指示（RunMonitorView）

- **下载**：`runApi.logs` 全量拉取 → Blob → `a[download]`，文件名 `pipelinerun-<runId>-<task>.log`。
- **按 task 折叠**：日志面板按 task 分组折叠（默认展开失败任务、折叠成功任务；>8000 字符默认只渲染尾部 + 展开全部）。
- **流式指示**：轮询期间 task 行显示 `● 实时` live-dot（运行活跃时显示）；「跟随刷新」开关（关闭即冻结视图便于复制）。真实权重/产物经 runner→hub 回流协议（`shared/runner-reflux-spec.md`）回流，前端不自行拼装流。

### 8.x.2 ⌘K 非组件资源直达

`utils/search.ts` 增 `nav` 类型（id = 路由 path）；`useGlobalSearch.ts` 客户端静态池 `NAV_HITS`（总览/服务树/运行中心/平台管理四 section），不依赖资源索引与服务端 `/search`；结果追加在资源命中之后、整体截 `SEARCH_LIMIT`。无法直达详情的资源明确提示「前往 <类型> 列表」而非静默无结果。

### 8.x.3 表格窄屏适配（CSS-only）

`styles/tokens.css` `@media (max-width: 768px)`——`.card { overflow-x: auto }`（容器横向滚动，不裁列）+ 单元格收紧 + toolbar 换行 + 栅格单列。首列 `position: sticky; left: 0` 冻结关键列。不引入响应式断点重构。

### 8.x.4 运行中心组件筛选 + 触发人筛选

- **组件筛选**：下拉数据源 `useResourceMap`，拼进 `buildQuery()` → `componentId`（URL `?component=` 同步，延续 runCenter URL 契约）。
- **触发人筛选**：hub `GET /runs` 增 `triggeredBy` 参数（`FindAll` 5 参，对齐既有 `createdAfter` 模式），console 出输入框 → `?triggeredBy=`。

### 8.x.6 一致性校验

| 维度 | 结论 |
| --- | --- |
| 概念一致性 | 「折叠分组/跟随刷新/URL 契约键」沿既有 runCenter 契约命名 |
