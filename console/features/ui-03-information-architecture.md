## 5. 信息架构（重设计核心）

### 5.1 左栏结构（极简导航，**恒 5 项**）

> **设计铁律（S5）**：左栏条目数 = `3(主区:总览/服务树/运行中心) + 2(平台管理) = 恒 5`，**与 Org/Service/Component 数量无关，也与用户行为无关**。任何"会变长"的东西都不许进左栏 —— 包括资源树，也包括"最近访问"这类随使用累积的列表。
> 原型对应：`MAIN_NAV`（3 项）+ `ADMIN_NAV`（2 项），`renderRail()` 不读任何资源数据。

```
┌──────────────┐
│ ▌ SDP Console ⟨⟨│  品牌 + 折叠（268 → 64 图标态）
├──────────────┤
│ 总览          │  ┐ 主区（不挂分组标签）——固定 3 项
│ 服务树        │  │ 顺序 = 用户心智顺序：
│ 运行中心      │  ┘ 看态势 → 找资源 → 巡视运行
├──────────────┤
│ 平台管理      │  ┐ 仅平台管理员可见
│  用户与权限    │  │
│  接入管理     │  ┘
├──────────────┤
│ 👤 张三      │  底部：用户（主题/灰阶/设计备注在顶栏）
└──────────────┘
```

**左栏条目语义**（顺序即上表自上而下）：

| 序 | 区 | 项 | 路由 | 图标 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 1 | 主区 | 总览 | `/dashboard` | `grid` | 指挥中心 |
| 2 | 主区 | **服务树** | `/service-tree` | `layers` | **独立页**。Org→Service→Component 的浏览 + 增删改；**树只在页内出现** |
| 3 | 主区 | **运行中心** | `/runs?view=runs\|releases` | `play` | **跨组件巡视的唯一入口**。两个视图：运行 / 发布；视图可切换、各自带状态筛选（筛选真实生效） |
| 4 | 平台管理 | 用户与权限 | `/admin/permissions` | `shield` | 平台级角色 |
| 5 | 平台管理 | 接入管理 | `/admin/targets` | `cloud` | 目标健康 |

> **v4.1 调整（2026-09-15，用户反馈「左边菜单运行中心移动到资源服务树菜单下方」）**：
> ① 「运行中心」移到「服务树」正下方 —— 主区顺序由 `总览 · 运行中心 · 服务树` 改为 `总览 · 服务树 · 运行中心`（顺序 = 看态势 → 找资源 → 巡视运行）。
> ② **去掉「全局」「资源」两个分组标签**：调整后主区三项同处一段，旧标签要么只剩单个条目、要么语义不符（"运行中心"不是"资源"）。**单个条目下方的分组标题本身就是冗余**（§8.4 原则四），故主区不挂标签，仅保留「平台管理」这一个分组标题。
> ③ 条目总数不变（恒 5），S5 不变量不受影响。

> **v4 删掉的三项及去处**：
>
> | 删除项 | 原因 | 去处 |
> | --- | --- | --- |
> | 最近访问（≤5 pin） | 仍是"随用户行为变长"的列表，与"左栏恒定"自相矛盾 | 高频组件直达由 **⌘K** 承担（≤2 步），足够 |
> | 流水线（顶层菜单） | 它是**资源的一个视图**，不是导航目的地 | 归「组件详情 · 交付 · 流水线」（v4.4 起运行中心也不再单列该视图） |
> | 发布（顶层菜单） | 同上 | 并入「运行中心 → 发布」视图 |
>
> 收益：左栏从"10 项（含树时代的 12 项）"降到 **5 项**，且**导航结构 = 恒定的功能分区**，不再随平台规模/使用习惯漂移。

#### 5.1.1 为什么不把树放左栏（用户反馈，P6/S5）

| 风险 | 左栏承载全量树（初稿 v1，已否决） | 本方案 |
| --- | --- | --- |
| **条目无界增长** | `O(Org × Service × Component)`，组件越多左栏越长，折叠也不能根治（最终 500 组件 = 500 行） | 左栏恒 **5** 项，与资源数**完全解耦** |
| **首屏加载变慢** | 应用启动即拉全量树，阻塞首屏；树越大越慢 | 启动 **0 次**树请求；进服务树页才拉第 1 层，展开才拉下一层 |
| **深层定位靠翻** | 只能逐层点开找，深层节点要点 N 次 | **全局搜索 ⌘K** + 服务树页搜索，服务端 `/search` 直达 |
| **渲染压力** | 全量 DOM 常驻 | 虚拟滚动窗口，≥200 节点只渲染可见行 |
| **移动端/窄屏** | 树吃掉本已紧张的宽度 | 折叠态 64px，树在页内自适应 |

> **代价与补偿**：放弃"1 击进任意组件"。唯一补偿路径是 ① **⌘K 全局搜索**（键盘 2 步，支持模糊/路径匹配）；② **从运行/发布列表点入**（巡视路径天然可达）。多数实际路径是"先看到某条运行 → 进组件"，而非"先想进某组件"。（v4 删「最近访问」后，不再有 1 击直达 —— 这是刻意取舍：**导航恒定 > 1 次点击**。）

### 5.2 服务树页 `/service-tree`（R-8，规模化设计）

树不再"一次加载完"，拆成三层机制：

| 机制 | 行为 | 端点【后端依赖】 |
| --- | --- | --- |
| **懒加载** | 默认只请求 Org 级；展开 Org 才请求其 Services；展开 Service 才请求其 Components。折叠态挂 "N 项 · 点开时加载" 提示 | `GET /orgs` → `GET /orgs/:id/services` → `GET /services/:id/components` |
| **服务端搜索** | 搜索框输入即查，**不需要展开树**；结果行必须显示**所属路径**（`platform-eng / svc-b`）以区分同名组件 | `GET /search?q=&type=component,pipeline,service&limit=20` |
| **虚拟滚动** | 节点数 ≥200 时启用窗口化渲染，只渲染可见行 | — |

- 布局：**master-detail**——左卡 = 树面板（**自身 `overflow:auto` 独立滚动**，不再顶整体页面）+ 底部惰性提示条；右卡 = 选中节点详情（**只显示该节点自身信息**，如路径/仓库/语言/流水线数；同级节点已在左卡树中可见，不重复列表）/ 搜索结果列表。
- 树面板默认**只展开到 Service**，Component 层收起，降低首屏噪声。
- 该页同时承担增删改：`＋ 新建 Service`、`＋ 新建组件`（树节点 hover 行内 `＋`）、节点"编辑 / 删除"。**删除按钮的位置与语义**（v4.3 拍板）：① **删除不放在树行**，只在右侧详情面板的头部右侧（`进入组件详情` / `编辑` / `删除` 三按钮右对齐），避免误触整棵树的节点；② 点树节点（Org / Service / 组件）**只选中并刷新右侧详情**，**不**直接跳组件详情页，跳转仅由详情页「进入组件详情」触发；③ 三层节点（Org / Service / 组件）点击都有右侧详情页。④ **删除判定权唯一在后端**：前端只触发确认 + 渲染后端 verdict，不做数据判断；级联不满足时后端返回 `409 + {reasons}`，前端把逐层未清理清单渲染进"无法删除"弹窗。**完整论证、契约与级联规则见 附 C（N-15 后端依赖）。**
- 页面**不渲染**规模设计的解释性表格（那是文档内容）——理由见 §8.4。
- **原型实现注记**：`treeHtml()` 按 `S.open` 逐层展开、未展开节点挂 `N 项 · 点开时加载`；`SEARCH_HITS` 为服务端搜索的本地模拟；`mockDeleteNode()` 为**后端判定占位**（注释已明示），非前端业务逻辑。
> **落地态（R-8，2026-09-22）**：本表四项机制**均已实现**，端点全部存在（N-8 / N-9 已关闭，见 附 A）。有一处**显式差异**：折叠态提示**不显示具体 N**（懒加载下提前知道 N 就得先请求，与懒加载自相矛盾），改为「点开时加载」，计数已知时才显示「N 项 · 点开时加载」。完整记账见 **附 I**。

### 5.3 全局搜索（R-7，直达主路径）

- 顶栏搜索框 + `⌘K` / `Ctrl+K` 唤起浮层；输入即搜（防抖 200ms）。
- 结果**跨类型**：组件 / 流水线 / Service，每行 = 类型标签 + 名称 + **所属路径**。
- 键盘可达：↑↓ 选择、Enter 打开、Esc 关闭；上限 20 条。
- 打开行为：组件 → `/components/:id`；流水线 → `/pipelines/:id`（编辑器）；Service → 服务树页定位。
- **这是替代"树里翻"的主路径**——因此从 Later 提升为 Must-have。

### 5.4 组件详情 Tab 收敛（P3）

9 个平铺 Tab → **7 个主 Tab**（`环境` 升为顶级；仅「交付」带子 Tab）：

| 主 Tab | 子 Tab | 承接旧 Tab | 原型状态 |
| --- | --- | --- | --- |
| **概览** | — | overview | 已展开（KPI 卡 ×4，数据取 `GET /api/component/:uuid`） |
| **交付** ▾ | 流水线 / 运行 / 发布 | pipelines + runs + releases | 已展开（三子 Tab 均有内容） |
| **配置** | — | config | 已展开（左环境树 + 右 `values.yaml` 查看/编辑/导入/导出） |
| **环境** | — | environments | 已展开（分组 + 环境的增删改；新建环境走**两步向导**，环境详情为**对接配置面板**——接入方式三选一 + 凭据 + 连接测试，见 §7.12） |
| **制品** | — | artifacts | 已展开（§7.10：只读版本包清单，3 列——版本包(签名 URL 超链接)/构建时间/文件大小；顶部含归档与备份说明；无上传/删除入口） |
| **权限** | — | permissions | 已展开（§7.9：组件级 `component_role_bindings`，四种角色，owner 自动 `component-admin`） |
| **日志** | — | logs | 已展开（§7.11：运行日志聚合视图，`GET /runs/:id/tasks/:name/log`，级别筛选 + 搜索） |

- 默认落在**概览**；主 Tab 一行 7 个。
- 「交付」内的子 Tab 用横向 pill 切换；「配置」**不再**含子 Tab（`环境` 已独立成主 Tab）。
- **为什么把 `环境` 提为顶级**（2026-09-19 按原型回写）：环境是**组件对接的独立资源**（有自己的分组、目标、命名空间、values），且在「配置」页里还要作为**左侧选择器**出现——把它留在配置的子 Tab 里，会出现"在配置里选环境"与"管理环境"两处入口语义重叠。提为顶级后：`配置` = 针对某个环境的 values 编辑（左树即环境选择器），`环境` = 环境与分组的生命周期管理。**v3 的"6 主 Tab + 2 组子 Tab"作废。**
- **作用域主键**：详情页所有查询（概览 / 流水线 / 运行 / 发布 / 环境 / 参数 / 制品 / 权限 / 日志）统一以**组件 uuid** 为作用域主键（对齐 `GET /api/component/:uuid/...`）；原型以 `ComponentAPI` 内存模拟，入参统一 uuid。
- **理由**：`交付`（流水线/运行/发布）同属"软件分发主链路"，分组呼应产品主线「服务树 → 组件 → 环境 → 配置 → 流水线 → 运行」。

### 5.5 路由变更

| 路由 | 变更 |
| --- | --- |
| `/runs` | **唯一跨组件巡视页**。新增 `?view=runs\|releases` 子视图（v4：流水线/发布从独立页降为视图；v4.4：去掉「流水线」视图）+ `?phase=` 状态筛选 + `?page=`，可 deep link |
| `/pipelines` | ~~v2：改为全局流水线浏览页~~ → **取消顶层页**，redirect → `/service-tree`（v4.4 后不再有全局流水线视图，旧 deep link 落到资源浏览页而非"运行列表"，避免语义漂移） |
| `/releases` | ~~v2：改为全局发布浏览页~~ → **取消顶层页**，redirect → `/runs?view=releases`（**修复现状的语义漂移**：今天是 redirect →`/runs`，点"发布"旧链却看到运行列表） |
| `/service-tree` | **保留**（资源浏览 + 管理页）；左栏「服务树」（主区第 2 项）高亮到此。别名 `/catalog` 可保留 redirect |
| `/components/:id/...` | 子路由由 9 个收敛为 7 主（`overview`/`delivery`/`configure`/`env`/`artifacts`/`permissions`/`logs`），交付再用 `?sub=pipelines\|runs\|releases` 承载；旧子路由保留 redirect 兼容 deep link |
| `/search` | **新增（前端浮层，非路由页）**：`⌘K` 唤起，不占路由；如需 deep link 可支持 `/search?q=` |

> **为什么视图用 query 而不是嵌套子路由**（N-13，详见 **附 B**）：v4 已判定「流水线/发布」是**视图不是页面**，`?view=` 是唯一不在 URL 层把它们升格回页面的选项；且 `/runs` 本身没有"父容器内容"，嵌套会造出假层级与 `/runs/runs`。配套 4 条实现约定：① `view` 缺省归一化（`/runs` → `replace` 为 `/runs?view=runs`）；② 面包屑第二段与 `RUN_VIEWS` 常量同源，禁建映射表；③ 视图切换与筛选一律 `replace`，仅详情下钻 `push`；④ 与"组件 Tab 用嵌套子路由"的分界 = **有无父容器 + 每个分页是否一等资源**。
