# SDP Console 前端补全计划 · 共享五态规范（含 403 按钮规则）

> 落盘日期：2026-10-11 · 既是计划 §1.1「五态」要求的**共享交付物**，也是第四期 §4.1「无权限（403）态与按钮规则」的正式规范。
> 适用：所有四期新增/改造的列表、抽屉、详情区、弹窗。每份工作项四件套中的「五态」条目均引用本文，仅补该项的特殊态。

---

## 1. 五态定义（空 / 加载 / 错误 / 成功 / 无权限）

计划 §1.1 规定：**所有新增列表必须覆盖空 / 加载 / 错误 / 成功 / 无权限五态**。状态一律「图标 + 文字 + 色」，灰阶下仍可辨（沿用原型契约）。

| 态 | 触发 | 图标 + 文字 | 色彩（明/暗主题均可辨） | 交互 |
|---|---|---|---|---|
| **加载** | 首次请求 / 翻页 / 刷新 | 旋转图标 + "加载中…" | 中性灰蓝 | 禁操作，骨架屏优先 |
| **空** | 200 且数据为空 | 空盒图标 + "暂无数据" + 引导动作（如"新建"） | 中性灰 | 展示主行动按钮（受权限门控） |
| **错误** | 非 2xx / 网络中断 / 超时 | 警告图标 + 错误摘要 + "重试" | 红（语义色） | 提供重试；不暴露原始堆栈 |
| **成功** | 200 且有数据 | 列表/详情正常渲染 | 常规前景色 | 常态 |
| **无权限** | 403 / 角色无该资源动作 | 锁图标 + "无权限查看" + 所需权限提示 | 橙（提示色，区别于错误红） | 见 §3 三策略 |

### 1.1 灰阶可辨规则
- 五态图标各自形状不同（旋转/空盒/警告三角/对勾/锁），**不依赖色**即可区分；色仅作辅助。
- 暗主题下图标与文字对比度 ≥ 4.5:1；明主题同上。回归清单（计划 §12）每期复查。

### 1.2 加载态细化
- 首屏用**骨架屏**（占位块），翻页用行内 spinner，避免全列表闪烁。
- 加载超 8s 自动降级为错误态（"加载超时，点击重试"），不无限转圈。

## 3. 无权限三策略与按钮规则（第四期 §4.1 核心）

权限判定**永远以后端 verdict 为准**，前端不持有业务判定（沿用原型删除类操作模式）。前端仅决定"无权限时按钮怎么呈现"。

| 策略 | 适用场景 | 行为 | 示例 |
|---|---|---|---|
| **隐藏** | 用户几乎不可能拥有该入口（平台级能力） | 入口不渲染 | 平台运维视图（Runner/配额）对非 `org:manage` 用户完全不显示 |
| **禁用 + tooltip** | 入口可见但当前角色不可执行，且操作可逆/低风险 | 按钮 disabled，hover 显示所需权限 | "新建组件"对仅 `component:read` 用户禁用，tooltip：需 `component:create` |
| **可点击后拦截** | 高风险操作需明确"为什么被拦"、或入口需暴露以引导申请 | 按钮可点，点击弹拦截说明 + 引导（联系管理员/申请权限） | 生产晋级对无 `approval:approve` 用户可点，弹"需审批权限，联系组件管理员" |

### 3.1 tooltip / 拦截说明规范
- 一律显示**所需权限标识**（如 `component:manage`），不写模糊文案。
- 拦截弹窗含：操作名、缺失权限、建议动作（联系谁 / 走哪条申请流）。
- 锁图标态（列表级 403）文案固定为"无权限查看"，并附"所需权限：`<action>`"。

### 3.2 权限态与加载态的顺序
- 先判 403（无权限态）→ 再判加载 → 再判空/错误/成功。避免对无权限用户发起不必要的列表请求（节省后端与审计噪声）。

## 4. 落地与回归

- **设计评审**：每工作项四件套的「五态」条目必须引用本规范并列出 §2 中对应项；未覆盖五态的列表不过审（计划 §12）。
- **联调校验**：用无权限 token 实测 §2 每个列表的 403 呈现（隐藏/禁用/拦截三策略各取样）。
- **回归清单**：每期结束复查灰阶可辨性、明暗主题、四态 + 无权限态是否覆盖新增页面。

> 本规范为**共享依赖**，各期前端 spec 文档不再重复定义五态，仅引用并标注特殊态（如 4.5 状态枚举修正影响的是"发布/环境状态徽章"，非列表五态；5.5 实时日志区的"断线重连"属错误态子类）。
