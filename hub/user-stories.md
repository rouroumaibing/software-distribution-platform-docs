# Software Distribution Platform · User Story 设计

角色定义:
- **平台管理员**:管理组织、集群接入、全局角色
- **组件负责人**:某个组件的 Admin,管配置/流水线/权限
- **研发工程师**:日常触发构建/发布、查看运行记录
- **审批人**:对发布任务做审批决策
- **集群接入方**:负责把自己的 K8s 集群接入平台(可能是运维/SRE,也可能是另一个厂商)

状态标记:✅ 已有代码脚手架 ｜ 🚧 部分实现 ｜ ⬜ 未开始

---

## 一、hub(控制平面)

### Epic 1:组织与服务树
- ✅ 作为平台管理员,我希望创建组织后自动生成对应的服务树,以便不用额外操作就能开始组织服务/组件
- ✅ 作为研发工程师,我希望能查看某个组织下的服务树结构,以便按层级找到我负责的组件
- ⬜ 作为平台管理员,我希望邀请用户加入组织并分配初始角色,以便新用户登录后能看到应有的数据(目前 JIT 建的用户 `OrgID` 是空的,见 Keycloak 集成里的遗留问题)

### Epic 2:服务与组件管理
- ✅ 作为组件负责人,我希望创建/编辑/删除组件,并关联其代码仓库地址,以便流水线知道去哪拉代码
- ✅ 作为组件负责人,我希望组件创建成功后自动获得该组件的 Admin 权限,以便不用额外申请就能配置后续内容(`ComponentService.Create` 里的 TODO)
- ⬜ 作为组件负责人,我希望在删除组件前被提醒"是否还有运行中的发布",以避免误删

### Epic 3:环境管理
- ✅ 作为组件负责人,我希望给组件配置多个环境(测试/生产),并指定各自的目标集群和命名空间,以便流水线知道往哪部署
- ⬜ 作为平台管理员,我希望生产环境的部署强制要求审批,即使流水线作者没主动配置审批阶段,以避免误操作绕过管控(`Environment.EnvType` 字段已就绪,策略校验逻辑待写)

### Epic 4:配置管理
- ✅ 作为组件负责人,我希望给组件设置全局配置和环境级覆盖配置,以便同一份流水线定义能适配不同环境的参数差异
- ✅ 作为组件负责人,我希望敏感配置(密钥类)不以明文存库,以满足安全合规要求
- ✅ 作为安全审计人员,我希望每次配置变更都有审计记录(谁、何时、改了什么),以便事后追溯
- ⬜ 作为组件负责人,我希望删除配置前能看到旧值写入审计记录,而不是丢失(`ComponentConfigService.Delete` 的 TODO)

### Epic 5:多集群接入
- ✅ 作为平台管理员,我希望注册一个新的 K8s 集群(厂商、region、状态),以便流水线能把任务调度过去
- ✅ 作为集群接入方,我希望我的集群只需要对外发起连接(不需要开放入站访问),以降低跨云网络打通的成本
- ⬜ 作为平台管理员,我希望在集群离线超过一定时长后收到告警,以便及时处理接入异常

### Epic 6:流水线定义
- ✅ 作为组件负责人,我希望创建流水线并定义多个顺序执行的阶段,每个阶段内可以有多个并行子任务,以便描述"构建→归档"或"审批→部署→测试"这类流程
- ✅ 作为组件负责人,我希望 Build 子任务既能直接填内联命令(如 pytest/go build)也能引用仓库脚本(build.sh/run.sh/test.sh),而 Release 子任务直接施加 chart/manifest 软件单元(从参数管理注入 values),以便复用团队既有脚本与软件包,而不用在界面上手拼命令
- ✅ 作为组件负责人,我希望流水线每次结构性编辑都会生成新版本快照,以便历史运行记录不会因为后续编辑而对不上
- ⬜ 作为组件负责人,我希望能对比两个版本之间的差异,以便review 变更内容

### Epic 7:流水线执行与运行记录
- ✅ 作为研发工程师,我希望触发一次流水线运行,并查看整体执行状态和每个任务节点的状态,以便掌握发布进度
- ✅ 作为研发工程师,我希望运行记录长期保存在数据库里(不是只存在 K8s CR 里),以便几个月后依然能查历史
- ⬜ 作为研发工程师,我希望实时看到任务执行的日志流,而不是等结束后才能看
- ⬜ 作为研发工程师,我希望能取消一个正在运行中的流水线

### Epic 8:审批
- ✅ 作为审批人,我希望在审批阶段收到待办,批准或拒绝后流水线自动继续或终止
- ⬜ 作为审批人,我希望审批超时后流水线自动失败,而不是无限期挂起(`ApprovalConfig.TimeoutSeconds` 字段已就绪,超时检测逻辑待写)

### Epic 9:产物管理
- ✅ 作为研发工程师,我希望查看某个组件历史构建产出的版本包列表并下载,以便回溯排查问题
- ⬜ 作为研发工程师,我希望产物下载走带时效的签名链接,而不是直接暴露存储地址(`DownloadURL` 待接对象存储 SDK)
- ⬜ 作为平台管理员,我希望设置产物保留策略,过期自动清理,以控制存储成本

### Epic 10:权限管理
- ✅ 作为组件负责人,我希望给团队成员分配"查看/编辑/创建/删除"等不同级别的权限,并且没有分配等于没有权限
- ⬜ 作为平台管理员,我希望能自定义角色(不局限于内置的 Viewer/Editor/Admin),以适配公司自己的权限颗粒度

### Epic 11:认证(Keycloak)
- ✅ 作为研发工程师,我希望用公司已有的 SSO 账号登录,不用单独注册,以降低使用门槛
- ✅ 作为系统,我希望第一次看到某个 Keycloak 用户的合法 token 时自动建好本地用户,以免需要人工开户
- ⬜ 作为平台管理员,我希望新用户首次登录后有一个"待激活/待分配组织"的引导流程,而不是登录后什么都看不到

## 二、runner(集群执行引擎)

### Epic 1:CRD 与类型定义
- ✅ 作为平台开发者,我希望用 `PipelineRun`/`TaskRun`/`Rollout` 三个 CRD 声明式地描述执行状态,以便复用 K8s 自身的调谐、审计、`kubectl` 可观测能力

### Epic 2:DAG 调度
- ✅ 作为系统,我希望 Reconcile 每次只推进"依赖已满足的一批任务",而不是一次性铺开整个 DAG,以便自然支持并行子任务和增量恢复
- ✅ 作为系统,我希望任意一个任务失败后,整个 PipelineRun 停止调度新任务并标记失败,而不是继续跑无意义的后续步骤
- ⬜ 作为研发工程师,我希望某个任务失败后能选择"从失败节点重试"而不是重新跑整条流水线

### Epic 3:任务执行
- ✅ 作为系统,我希望脚本类任务的 Job 自动包含"检出代码 → 拉取上游产物 → 执行脚本"三段式初始化,以便脚本作者不用关心这些平台细节
- ✅ 作为系统,我希望任务失败后按 `RetryPolicy` 配置的次数和退避时间自动重试,而不是人工介入
- ⬜ 作为系统,我希望任务日志能实时流式回传,而不是等 Pod 结束才能拉取

### Epic 4:灰度发布
- ⬜ 作为研发工程师,我希望部署任务按配置的权重步进策略(比如 10%→50%→100%)逐步放量,每步观察健康指标后再继续
- ⬜ 作为系统,我希望健康检查连续失败达到阈值后自动回滚,而不需要人工干预
- ⬜ 作为研发工程师,我希望能在灰度过程中手动暂停或立即全量回滚

### Epic 5:Hub 长连接
- ✅ 作为集群接入方,我希望 Agent 只需要对外发起连接就能被 Hub 纳管,不需要开放 K8s API Server 的入站访问
- ✅ 作为系统,我希望连接断开后能自动重连并恢复心跳,而不需要人工重启
- ⬜ 作为系统,我希望重连后能对账"哪些下发的任务还没执行完",避免断线期间的指令丢失或重复执行

### Epic 6:多集群部署
- ⬜ 作为集群接入方,我希望用一个 Helm Chart 一键把 Agent 部署到自己的集群,而不需要理解内部实现细节
- ⬜ 作为平台管理员,我希望 Agent 升级时有版本兼容性检查,避免新版本 Hub 跟旧版本 Agent 不兼容导致故障

## 三、console(前端控制台)

### Epic 1:登录与认证
- ✅ 作为研发工程师,我希望打开控制台未登录时自动跳转 Keycloak 登录页,登录后自动跳回原来想访问的页面
- ⬜ 作为研发工程师,我希望 token 快过期时静默刷新,而不是突然被强制登出打断操作

### Epic 2:服务树导航
- 🚧 作为研发工程师,我希望在左侧看到"服务树→服务→组件→流水线→阶段→运行记录"的层级导航,点击任意一层能钻取下去(目前只有 Dashboard 列出组织,导航树还没做)
- ⬜ 作为研发工程师,我希望能搜索定位到具体的组件或流水线,而不用逐层点击

### Epic 3:组件管理
- ⬜ 作为组件负责人,我希望在组件详情页里切换"环境管理/配置管理/流水线管理/产物管理/权限管理"几个 Tab,对应 hub 那五块能力
- ⬜ 作为组件负责人,我希望配置管理页面里敏感配置显示为打码状态,不直接明文展示

### Epic 4:流水线可视化编排
- ⬜ 作为组件负责人,我希望拖拽式编排流水线的阶段和子任务,而不是手写 JSON
- ⬜ 作为组件负责人,我希望 Build 子任务的配置项是"命令 + 参数"(或"脚本路径 + 参数")两个输入框而非一整条拼接字符串;Release 子任务的配置项是 chart/manifest 源 + 从参数管理注入的 values
- ⬜ 作为组件负责人,我希望编辑保存后能看到版本号变化,并可以查看历史版本

### Epic 5:运行记录与执行监控
- ⬜ 作为研发工程师,我希望触发一次运行后看到 DAG 图上每个节点的实时状态(排队/运行/成功/失败),而不是纯列表
- ⬜ 作为研发工程师,我希望点开某个任务节点能看到实时日志流
- ⬜ 作为审批人,我希望在运行详情页直接完成审批操作,不用跳转别的地方

### Epic 6:灰度发布监控
- ⬜ 作为研发工程师,我希望看到部署任务当前的灰度权重、健康检查结果,并能手动暂停/继续/回滚

### Epic 7:产物管理
- ⬜ 作为研发工程师,我希望在组件的产物列表里按版本浏览、下载构建产物

### Epic 8:权限管理
- ⬜ 作为组件负责人,我希望在权限页面搜索用户并分配角色,查看当前谁对这个组件有什么权限

## 里程碑建议(按依赖关系排序)

1. **M1 · 打通单条流水线全链路**:hub 触发运行 → runner Reconcile → Job 真正跑起来 → 状态回传 → console 能看到结果(目前最大缺口是 hub 的 `gateway/` 和 runner 的 connector handler 注册还没接起来)
2. **M2 · Console 补上服务树导航 + 流水线可视化编排**:没有这两块,平台目前只能靠调 API 使用
3. **M3 · 灰度发布**:`runner` 的 `pkg/canary/` + `RolloutController`,加上 console 的灰度监控面板
4. **M4 · 多集群规模化**:Helm Chart 一键接入、Agent 版本兼容性检查、集群离线告警
