## O-37 审计 / 运行日志 / 制品保留与 GC（C1）

**目标**：定义分级保留基线 + 定时 GC，防止审计日志、`pipeline_run`/`task_run` 运行日志、历史制品版本无限增长；与 O-26 备份策略协同。

**现状 / 证据**：O-16 仅覆盖制品 `expires_at` GC 与上传对账；审计日志、运行日志、历史制品版本的保留期与清理策略未定义，会无限增长。

**代码改动点**：
1. 与 O-26 协同定义保留基线：审计长留 / 运行日志短留 / 制品按版本数或时间滚删。
2. hub 内 scheduler / cron job 执行**分级 GC**：先报告后删（防误删进行中上传 / 合规所需审计），策略可配。

**验收 gate**：GC 按策略清理且不影响进行中数据；与 O-26 备份协同设计文档化。

**钢人结论**：中可落地，难点在策略拍板（GC 删错不可逆，须先定各数据类型留存基线再动手）。与 O-26 同属「数据生命周期」议题。
